# Walking WiFi 小程序原型

> 到店网络助手 · 查密码 + 一键复制 + 匿名贡献
> 后端复用 `https://api.lilcandi.xyz`，接口和安卓 App 完全一样

## 二、关于扫描能力的最终结论

### 2.1 真机实测可用，模拟器不支持

| 环境 | 结果 |
|---|---|
| **真机（Android）** | ✅ 能扫出周围 WiFi 列表 + 信号强度 |
| 微信开发者工具模拟器 | ❌ 报「开发者工具暂时不支持此 API 调试，请使用真机进行开发」 |

**之前的误判**：官方指南页写着「该系列接口已下架」，我据此判断扫不了。
实际是**指南文字没更新**，API 一直是活的——`typeof wx.getWifiList === 'function'` 为真，
真机调用返回完整列表。

**教训**：文档写的「下架」和 API 实际状态可能不一致，必须以真机运行结果为准。

### 2.2 自动连接受限，所以主路径是复制

`wx.connectWifi` 官方文档注明「Android 10 及以上的手机无法生效」。
所以产品主路径定为**复制密码 → 用户自己去系统里连**，这是 100% 可靠的。
若真机上 `connectWifi` 可用，密码卡片里会多一个「帮我直接连这个」按钮（加分项，不是主路径）。

### 2.2 Android 10 及以上，连接接口无效

[wx.connectWifi 文档](https://developers.weixin.qq.com/miniprogram/dev/api/device/wifi/wx.connectWifi.html) 原话：

> Android 微信客户端 7.0.22 以上版本，connectWifi 的实现在 **Android 10 及以上的手机无法生效**

安卓 10 起，普通应用不能改 WiFi 配置（只有系统设置能）。微信也是普通应用，一样受限。
2025 年 90%+ 的活跃设备是 Android 11-15，所以这个接口基本等于不存在。

### 2.3 那「取巧」在这里

**把连接动作交给系统做。**

查到密码后，小程序生成标准 WiFi 串：

```
WIFI:T:WPA;S:门店WiFi名;P:密码;;
```

用户复制走，或者用**系统相机**扫这个二维码 —— 系统会直接弹「连接到 XXX」，点一下就成。

**执行连接的是系统，不是小程序，所以不受限制。**

这就是本方案的核心：**把需要权限的操作从 App 转移给系统。**

## 三、怎么跑起来

### 3.1 导入

1. 装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 打开工具 → 导入项目 → 目录选 `K:\WIFI\walking-wifi\miniprogram`
3. AppID 选「测试号」就能跑（`project.config.json` 里现在是 `touristappid`）
4. 编译，首页就是查询页

### 3.2 必须改的一处配置

**后端域名要加进白名单**，否则 `wx.request` 会被拦：

开发者工具 → 详情 → 本地设置 → 勾上 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**

真机/上线前要去 **微信公众平台 → 开发 → 开发设置 → 服务器域名** 里加：
```
request 合法域名: https://api.lilcandi.xyz
```

## 六、已知的不确定点（实测才知道）

| 项 | 为什么不确定 | 怎么验 |
|---|---|---|
| `wx.getConnectedWifi` 能不能用 | 整章标「已下架」，但 API 页还在。有人报 `12001 system not support` | 在开发者工具和真机上各试一次，看 `autoSsidNote` 显示「已识别当前连接」还是「手动输入」 |
| 系统相机扫 WiFi 串的识别率 | 各家 ROM 实现对 `WIFI:` 串的支持不一致 | 找 3 台不同品牌手机，把生成的串做成二维码扫一下 |
| 微信扫一扫能否识别 WiFi 二维码 | 有时能弹「连接」，有时只显示文本 | 同上 |

**这三条决定了产品的最终形态，建议先验完再往下做。**

## 七、上线前必须处理

| 项 | 说明 |
|---|---|
| **主体** | 个人主体类目受限，建议企业/个体工商户 |
| **类目** | 不要选和「网络破解」沾边的。建议「工具 → 效率」或「生活服务」 |
| **文案** | 全站不要出现「破解」「万能」「蹭网」。现在代码里已经避开了 |
| **域名备案** | `api.lilcandi.xyz` 在小程序后台要作为 request 域名，需 HTTPS（已是）+ 可访问 |
| **隐私政策** | 小程序必须有小程序隐私协议，说明收集什么（本产品只收 SSID + 密码，不收集身份信息） |

### 审核风险提示

2020 年工信部点名 WiFi 万能钥匙整改，理由是「非法收集用户 WiFi 信息」。
本产品的匿名贡献如果被解读成「后台采集他人 WiFi」，风险就在这里。

**规避做法**（代码里已经这样设计）：
- 不做后台自动采集，只做用户主动填写
- 页面明确写「仅用于公开公用网络」
- 贡献不上传设备标识、位置、账号

## 八、下一步建议

1. **先验三件事**（在开发者工具 + 2 台真机上）
   - `getConnectedWifi` 通不通
   - 后端 `lookup` 能不能拿到数据
   - 系统相机扫 WiFi 串识别率

2. **通过了再补功能**
   - 历史记录（查过的店）
   - 二维码 canvas 渲染（现在只给串，需要接 QR 编码库）
   - 到店提醒（基于定位，可选）

3. **不要一上来做完整版**
   先拿 3 个朋友在真店里试「查密码 → 复制 → 连上」这一步顺不顺。
   不顺就说明用户不接受多一步操作，回退到「App + 小程序导流」。
